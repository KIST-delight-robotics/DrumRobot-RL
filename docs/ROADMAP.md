# ROADMAP

현재 baseline (성공률 77.2%) 에서 같은 구조로 더 학습해도 의미 있는 개선은 어렵다고 판단. **새로운 가설을 도입하면서 다시 시작** 하는 것이 자연스러운 다음 단계.

우선순위는 **"직관적이고 효과를 빠르게 확인할 수 있는 것부터"**.

---

## 가설 백로그

### H1. 속도 보상 상한 제거 [직관적, 우선]

현재 상향 속도 보상이 특정 높이까지만 활성화된다. 그 위로는 보상이 끊겨서 정책이 더 이상 안 올라간다. 타격 후 리바운드가 충분히 일어나지 않는 직접 원인일 가능성이 있다.

→ 상향 속도 보상의 상한을 제거하거나 완화한 뒤 동작 변화 관찰.

### H2. 타격 후 리바운드 자체에 대한 동기 [직관적]

다음 목표 노트가 곧 있으면 정책이 자연스럽게 다시 올라가지만, 휴지 구간에서는 그렇지 않을 가능성이 있다 (미검증). 휴지 구간에서도 idle 자세로 복귀하도록 명시적 보상이나 강제가 필요할 수 있다.

→ 휴지 구간에서의 정책 동작을 먼저 측정. 문제가 있으면 idle 복귀 항 추가 검토.

### H3. 양손 배정을 정책이 학습 [실험적, 후순위]

현재는 환경이 거리 기반 비용으로 양손을 배정한다. 정책이 직접 배정도 학습하게 하려면, observation에 "양손이 직전에 어느 악기를 언제 쳤는지" 를 추가하는 방향으로 시도해볼 수 있다.

→ 효과 불확실. H1, H2가 직관적이라 우선.

## 06의 한계 중 풀어야 할 것 (우선순위 순)

1. **연주 퀄리티** — 인접 드럼 오타격 (미드 40%, 하이 44%), 멀리 있는 드럼 놓침 (플로어 30%, 라이드 27%, 우크래시 26%). H1과 H2가 직접 영향을 미칠 영역.
2. **타이밍 정확도의 정량 평가** — 현재는 ±10 step 윈도우 안의 hit 여부만 본다. 윈도우 안에서도 정확도 차이는 추적되지 않음. 평가 메트릭부터 만들 것.
3. **실제 MIDI 분포에서의 fine-tuning** — 06은 랜덤 RDS로만 학습됨. 실제 음악 패턴 (빠른 연타, 동시 양손 노트, 트리플렛 등) 에서의 성능은 별도 평가 필요.
4. **자가 충돌 회피** — 과거 point-reaching 실험에서 검증된 soft barrier + hard limit 패턴을 자가 충돌에 적용. 페널티 영역에서 부드럽게 회피를 학습 → 실제 충돌 시 episode 종료의 2단계 구조.

## 모델 구조 측면의 가능성 (필요 시)

현재 정책은 MLP (`[256, 160, 128]`, ELU) 다. 06번에서 미래 K개 이벤트를 observation에 직접 넣는 방식으로 MLP만으로도 시간 정보를 처리하고 있지만, 다음과 같은 상황이 오면 시계열 모듈 (GRU, Transformer) 도입을 검토할 만하다.

- K개 이벤트로는 부족할 만큼 긴 컨텍스트가 필요해질 때 (예: 한 마디 전체를 보고 다음 동작 결정).
- 과거 동작의 흐름이 중요해질 때 (예: 방금 친 박자에서 자연스럽게 이어지는 모션).

### 머리 / 페달 통합 (4 DOF)

현재 9 DOF (허리 1 + 양팔 8) 만 RL 대상. 머리 2 + 페달 2를 RL 프레임워크에 포함시킬지, 별도 룰베이스로 둘지 결정이 필요하다. 악보에 반응해야 하지만 정밀도 요구는 낮음.

## 별도 프로젝트와의 통합 (참고)

### LLM 인터랙션 (별도 프로젝트)

LLM이 키보드 입력 대신 로봇에 명령을 전달하는 시스템이 별도로 진행 중이다. 본 RL 프로젝트와 독립적으로 개발되며, 통합 시점에 한 가지 이슈가 예상된다.

본 정책은 시뮬레이션 상의 로봇 상태를 입력으로 받아 액션을 생성하는 구조다. 실제 하드웨어에 이식하려면 실제 로봇의 관절 센서값을 받아 액션을 만드는 형태로 드럼 컨트롤러에 맞춰야 한다. 통합 시점에 다룰 문제.
