# Drum Striking

> **한 줄 요약**: 양팔 9-DOF 로봇이 시뮬레이션에 배치된 드럼 객체를 "도달"이 아닌 "타격"하도록 학습시킨 실험.
>
> **Status**: 실패 (체크포인트 700K steps)
>
> **시기**: 2026-02 ~ 2026-03

---

## 1. 동기 (Why)

이전 실험(`pr`, point reaching)에서 양팔 9-DOF가 임의의 3D 점에 수렴할 수 있음을 확인했다. 그 다음 자연스러운 단계는 **점이 아닌 실제 드럼 객체에 "타격"**을 학습시키는 것이다.

`pr`에서 `dr`로 넘어오면서 바뀌어야 할 것들:
- 타겟이 임의 점이 아닌 8개 고정 드럼 중 하나 (양팔 조합 38개)
- 단순 도달이 아닌 "내려치고 튕겨나오는" 동적 동작
- 손이 어느 드럼을 향해야 하는지 정책이 알아야 함

이 실험은 점 도달 보상 구조를 거의 그대로 유지한 채, **타겟을 드럼 위치로 바꾸고 속도/방향 보상을 추가하면 타격 동작이 나올지** 검증하는 것이 목적이다.

---

## 2. 문제 정의 (What)

- **목표**: 8개 드럼(`snare`, `floor`, `mid`, `high`, `hihat`, `ride`, `crash_r`, `crash_l`) 중 양팔에 할당된 두 드럼을 각각 타격
- **타격 성공 조건**: `impact_armed` 상태(드럼 xy 범위 안에서 하향 속도 ≥ 1.0 m/s를 거침)에서 rebound(상향 속도 ≥ 0.3 m/s) + z-margin 안쪽 → `hit_mask = True`
- **에피소드 성공**: 양손이 모두 한 번씩 hit
- **실패 기준**: 없음 (관절 제한을 넘어도 종료하지 않음. `limit_pen`으로만 억제)

---

## 3. 설계 (How)

### `pr` 대비 변경점 한눈에

| 항목 | `pr_cfg` / `pr_env` | `dr_cfg` / `dr_env` |
|---|---|---|
| 관측 차원 | 30 | **50** |
| 타겟 | `target_min/max` 박스 안 균등 샘플링 | `instruments` 8개 위치 + `drum_set` 38쌍에서 선택 |
| 성공 정의 | 0.1m 이내 10스텝 hold | impact_armed → rebound + z margin |
| died(early term) | 관절 제한 초과 시 -5 후 종료 | 사용하지 않음 |
| 보상 항 수 | 6 | 9 |
| 성공 보상 | 2.0 (hold 성공) | 50.0 (first_hit) |

### 관측 (50차원)

| 항목 | 차원 | 의도 |
|---|---|---|
| 관절 위치 | 9 | `pr`과 동일 |
| 관절 속도 | 9 | `pr`과 동일 |
| 목표 one-hot (L) | 8 | 8개 드럼 중 어느 것이 왼손 타겟인지 |
| 목표 one-hot (R) | 8 | 오른손 타겟 |
| 위치 오차 (팁 - 목표) | 6 | `pr`과 동일 |
| 팁 속도 | 6 | **신규**. 타격 동작은 속도 의존적이므로 정책이 속도를 직접 봐야 함 |
| `success_L`, `success_R` | 2 | **신규**. 이미 친 손인지 |
| `impact_armed_L`, `impact_armed_R` | 2 | **신규**. 내려치는 사이클에 진입했는지 |

`pr`이 절대 좌표 + 오차였다면, `dr`은 **"어느 드럼이 타겟인가"(one-hot) + 속도 + 타격 사이클의 상태**까지 정책에 보여준다. 절대 좌표(`targets`)는 빠지고 그 자리를 one-hot이 대신한다.

### 행동 공간

`pr`과 동일: 9차원 연속 행동, `action_scale = 0.03`.

### 보상 설계

`compute_reward_terms`에서 다음 항들을 만든다.

- **`xy_term` (음수)**: 양손의 드럼 중심까지 xy 평면 거리 합. `pr`의 `dist_term`을 xy로만 좁힘.
- **`z_term` (음수)**: 드럼 표면까지 z 오차의 절댓값 합. **xy와 z를 분리한 이유**: 드럼 타격은 평면에서 위치를 맞춘 뒤 z 방향으로 내려치는 동작이므로 두 축의 의미가 다르다.
- **`exp_xy_term`, `exp_z_term`**: `exp(-k·dist)`, `k_xy=8`, `k_z=10`. `pr`의 단일 exp를 두 축으로 분리.
- **`downward_term`**: `(-vz)`를 양수로 클램프한 값을 **`near_xy` ∧ `near_z` ∧ `(1 - impact_armed)`** 마스크로 곱함. 드럼 가까이 있을 때, 아직 내려치는 단계 진입 전이라면 하향 속도를 보상.
- **`upward_term`**: `(+vz)`를 양수로 클램프한 값을 **`near_xy` ∧ `near_z` ∧ `impact_armed`** 마스크로 곱함. armed 상태에서는 위로 튕기는 속도를 보상.
- **`action_l2`, `joint_vel_l2`, `limit_pen`**: `pr`과 동일 형태의 정규화 항.
- **`first_hit` 보너스**: 한 손이 처음 hit한 step에 +50. `pr`의 `success_bonus=2.0`보다 한 자릿수 크게.

`pr`에 있던 `died` 패널티는 제거. 관절 제한을 넘어도 죽이지 않고 `limit_pen`으로만 부드럽게 억제한다.

### 타격 판정 (`_check_hit_for_hand`)

`impact_armed`라는 1비트 잠금을 둔다:
- xy 범위 안에서 `vz ≤ -1.0` → `impact_armed = True`
- xy 범위 밖으로 나가면 자동 해제
- armed 상태에서 `vz ≥ +0.3` 이면서 z 마진 안이면 `hit`, 동시에 armed 해제

이 구조는 단순한 거리 기반 hit 판정 대신 **"내려쳤다가 튕겨 나오는 시퀀스"**를 요구한다.

| 항목 | 값 | 비고 |
|---|---|---|
| 병렬 환경 | 128 (cfg) | |
| 에피소드 길이 | 5s | `pr`과 동일 |
| action_scale | 0.03 | `pr`과 동일 |
| 학습 step | 700K | |

## 4. 결과

![GIF](./gif/02.gif)

보상 그래프 첨부 예정

```
reward=0.593 | left_xy_dist=0.049 | right_xy_dist=0.040 | left_z_err=0.045 | right_z_err=0.043
downward_term=0.164 | upward_term=0.045 | action_l2=4.974 | joint_vel_l2=0.905 | limit_pen=0.000
impact_armed_L=0.135 | impact_armed_R=0.272 | first_hit_L=0.000 | first_hit_R=0.000
```

이 메트릭 라인이 결과를 그대로 말해준다:

- **xy, z 모두 5cm 이내까지 좁힘**: `left_xy_dist=0.049`, `right_z_err=0.043`. 도달은 매우 잘 됨.
- **`impact_armed`에는 진입함**: 평균 13~27%의 시점에서 armed 상태가 켜져 있음. 즉 한 번씩 아래로 충분히 내려가긴 한다.
- **`first_hit`이 거의 0**: armed에는 들어가지만 **rebound(튕기는 상승) 조건을 거의 만들지 못함**. 결국 hit으로 인정되는 사이클이 학습 내내 거의 발생하지 않았다.
- **`downward_term`(0.164)이 `upward_term`(0.045)보다 큼**: 내려가긴 잘 하는데 튕기는 동작은 잘 안 나옴.

겉으로 보면 손이 드럼 위에 정밀하게 도달해 머무는, **"드럼 타격"이 아니라 "드럼 수렴"** 정책이다.

## 5. 무엇이 잘 됐는가

- **xy/z 분리**의 작동: 두 축에 대해 독립적으로 exp shaping을 걸면 각 축이 별도 정밀도로 수렴한다. 이후 모든 후속 task에서 유지되는 패턴.
- **8개 드럼 중 38개 양팔 조합**을 one-hot 관측으로 정책에 전달하면 단일 정책으로 모든 조합을 처리할 수 있음을 확인.
- **`impact_armed` 잠금**의 동작: 거리 조건만으로 hit을 판정하면 스쳐 지나가는 가짜 hit이 생기는데, 잠금 구조를 두면 "내려치는 사이클을 거친" 경우만 hit 후보가 된다. 판정 자체는 깨끗하다.
- **양팔이 동시에 서로 다른 드럼 위치로 수렴**하는 협응이 학습됨.

## 6. 한계와 막힌 점

핵심 문제는 단 하나로 요약된다: **위치 보상이 너무 강해서 정책이 "도달 후 정지"에 갇혔다.**

좀 더 분해하면:

- **`xy/z + exp_xy/exp_z`는 dense하고 항상 양수쪽으로 수렴 가능한 신호**. 타격을 안 해도 드럼 근처에 가만히 있으면 매 step 큰 보상을 받는다.
- **`downward_term`과 `upward_term`은 sparse**: `near_xy` ∧ `near_z`라는 좁은 영역에서만 켜진다. 정책이 거기 도달하기 전까지는 두 항이 0이라 학습 신호가 거의 없다.
- **`first_hit_bonus=50`은 매우 sparse**: armed→rebound 사이클을 실제로 만들어내야만 1회 발생. 거의 일어나지 않으니 정책이 이 보상을 의식하지 않는다.
- 결과적으로 **dense한 정지 보상 vs sparse한 동작 보상**의 비대칭으로, 학습이 dense 쪽으로 수렴.

이 한계는 보상 가중치 튜닝으로 우회를 시도해볼 수 있다(`down/up` 가중을 키우거나 `xy/z` 가중을 줄이거나). 그러나 **본질은 가중치가 아니라 보상의 시간 구조**이다. 도달 보상은 시간에 무관하게 항상 켜져 있고, 동작 보상은 특정 순간에만 활성화되어야 한다. 가중치 튜닝으로는 이 구조적 비대칭을 해소하기 어렵다는 판단으로 다음 실험으로 넘어갔다.

부차적인 문제:

- **`died`(early termination) 제거**가 잘한 선택이었는지 모호함. `pr`에서는 죽음 패널티가 학습 초기에 부정적인 동기(빨리 죽기)를 만들었지만, `dr`에서는 죽지 않으니 정책이 안전한 정지 자세로 더 쉽게 수렴.
- 메트릭에 `impact_armed`는 추적했으나 **armed → rebound 전이 실패의 원인 분석 도구**(왜 튕기지 못하는지 — 위치는 맞는데 z 속도 부호 전환이 안 되는지 등)가 부족.

## 7. 다음 단계로 넘어간 이유

학습된 정책이 **"드럼에 도달해서 머무는 동작"이지 "타격 동작"이 아니다.** `first_hit ≈ 0`은 700K step을 더 돌려도 크게 개선되지 않을 가능성이 높았다. 보상 구조 자체가 도달을 선호하기 때문이다.

다음 실험(`ds`, 03)의 방향은 명확해졌다:

> **보상을 "위치 + sparse 동작 보너스"에서 "동작 단계 자체를 phase로 모델링하고 phase별로 다른 보상을 켜는" 구조로 바꾼다.**

즉 IDLE → LIFT → DESCEND → RETURN 같은 FSM을 환경 측에 두고, 정책이 현재 phase를 관측으로 보면서, 각 phase에서 적합한 행동(예: LIFT 단계에서는 위로 가는 속도)에 dense 보상을 준다.

---

## 8. 회고 / 배운 점

- **"도달 보상 + sparse 행동 보너스"는 도달로 수렴한다.** 학습 신호의 시간적 분포가 정책 모양을 결정한다는 것을 체감한 실험. sparse 보상의 가중치를 키우는 것만으로는 해결되지 않는다.
- **정적인 보상 함수로 동적인 동작을 학습시키기 어렵다.** 보상이 시간에 무관한 양으로 정의되면 정책도 시간에 무관한 정지 자세로 수렴한다. 동작을 원하면 보상도 동작의 시간 구조를 따라야 한다.
- **`impact_armed` 같은 1비트 잠금 + 관측 노출**의 패턴은 이후에도 유효. 판정 로직과 학습 신호를 분리하는 데 유용하다.
- **xy/z 분리**, **속도 관측**, **one-hot 타겟 ID**는 이후 task에 모두 계승된다.
- **dense 신호와 sparse 보너스의 비대칭**이 학습된 정책의 형태를 결정한다는 교훈 — 보상 설계의 핵심 원칙으로 다음 실험에서 활용.
